# Bug Fix Workflow

標準化的除錯流程，確保不跳過環境檢查直接改程式碼。

## 步驟

### 1. 環境檢查優先

在修改任何程式碼之前，先確認以下事項：

- **瀏覽器快取**：請使用者 hard refresh（Ctrl+Shift+R）後確認問題是否仍存在
- **Console 錯誤**：檢查瀏覽器 Console 是否有相關錯誤訊息
- **Network tab**：確認所有 script、CSS 檔案是否正常載入（無 404 或載入失敗）
- **多瀏覽器測試**：如可能，在不同瀏覽器或無痕模式中測試

如果問題在清快取後消失，則不需要改程式碼，直接告知使用者原因。

### 2. 確認問題可重現

- 記錄重現步驟
- 確認不是快取或環境造成的假象
- 只有確認是程式碼問題後，才進入修改階段

### 3. 根因分析

- 使用 Grep 和 Read 工具追蹤問題來源
- 優先檢查最近修改過的檔案（git log / git diff）
- 確認是邏輯錯誤、依賴問題、還是載入順序問題

### 4. 修復

- 做最小範圍的修改，不做不相關的重構
- 如果涉及 theme/dark mode，確保邏輯 inline 在 HTML 中
- 修改後在本地確認修復有效

### 5. 修復後驗證

- 提醒使用者清除快取後測試
- 確認修復在 light mode 和 dark mode 都正常
- 確認沒有引入新的依賴或載入問題
- 在不同頁面測試相關功能是否一致

### 6. Commit & 記錄

- Commit message 附上根因描述（例如：「fix: dark mode toggle - 原因：外部 JS 載入順序問題」）
- 如果是容易再犯的問題，更新 CLAUDE.md 的 Debugging 區段
